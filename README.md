# Task Service

Сервис управления задачами с HTTP API на Go. Расширен поддержкой **периодичности задач**.

## Требования

- Go `1.23+`
- Docker и Docker Compose

## Быстрый запуск

```bash
docker compose up --build
```

Сервис доступен на `http://localhost:8080`.

Swagger UI: `http://localhost:8080/swagger/`

Если postgres уже запускался ранее со старой схемой:

```bash
docker compose down -v
docker compose up --build
```

## API

| Метод  | Путь                               | Описание                          |
|--------|------------------------------------|-----------------------------------|
| POST   | /api/v1/tasks                      | Создать задачу                    |
| GET    | /api/v1/tasks                      | Список задач                      |
| GET    | /api/v1/tasks/{id}                 | Получить задачу по ID             |
| PUT    | /api/v1/tasks/{id}                 | Обновить задачу                   |
| DELETE | /api/v1/tasks/{id}                 | Удалить задачу                    |
| GET    | /api/v1/tasks/{id}/occurrences     | Ближайшие даты повторений         |

## Периодичность задач

Поле `recurrence` опционально. Если не указано — задача разовая.

### Типы расписаний (`recurrence.type`)

| Тип               | Описание                              | Доп. поля                        |
|-------------------|---------------------------------------|----------------------------------|
| `daily`           | Каждые N дней от `start_date`         | `interval` (int, ≥ 1)           |
| `monthly`         | В конкретные числа месяца             | `month_days` ([]int, 1–30)      |
| `specific_dates`  | Только на указанные даты              | `dates` ([]RFC3339)              |
| `even_days`       | По чётным числам месяца               | —                                |
| `odd_days`        | По нечётным числам месяца             | —                                |

Все типы поддерживают `start_date` и `end_date` для ограничения диапазона действия.

### Примеры

**Каждые 2 дня:**
```json
{
  "title": "Ежедневный обзвон пациентов",
  "recurrence": {
    "type": "daily",
    "interval": 2,
    "start_date": "2025-01-01T00:00:00Z"
  }
}
```

**1-го и 15-го числа каждого месяца:**
```json
{
  "title": "Формирование отчётности",
  "recurrence": {
    "type": "monthly",
    "month_days": [1, 15]
  }
}
```

**По чётным числам до конца квартала:**
```json
{
  "title": "Инвентаризация",
  "recurrence": {
    "type": "even_days",
    "start_date": "2025-01-01T00:00:00Z",
    "end_date": "2025-03-31T00:00:00Z"
  }
}
```

**Ближайшие 5 дат повторений задачи:**
```
GET /api/v1/tasks/1/occurrences?n=5
```

## Архитектурные решения и допущения

### Хранение recurrence в JSONB

Расписание хранится как `JSONB`-поле в таблице `tasks`, а не в отдельной таблице.

Разные типы периодичности имеют разный набор полей. Отдельная таблица потребовала бы либо широкой таблицы с множеством NULL-полей, либо таблицы на каждый тип. JSONB — естественная модель для полиморфных конфигураций. При этом PostgreSQL позволяет индексировать отдельные поля JSON, что используется для индекса по `recurrence->>'type'`.

### Расписание хранит настройки, а не экземпляры

Сервис хранит *правило* повторения, а не создаёт отдельные записи на каждую дату. Это ответственность внешнего планировщика (cron). Эндпоинт `/occurrences` позволяет клиенту или планировщику вычислить нужные даты.

### `month_days` ограничен 1–30, а не 1–31

31-е число есть не в каждом месяце. Чтобы не было ситуации "задача за февраль не появилась, потому что 31-го не существует", максимум ограничен числом 30 — оно есть в каждом месяце.

### `start_date` по умолчанию — сегодня

Если `start_date` не передан, он устанавливается в текущую дату. Пользователь создаёт расписание — оно начинает действовать немедленно.

### Горизонт поиска NextOccurrences — 365 дней

Чтобы избежать бесконечного цикла для бессрочных расписаний, поиск ограничен 365 днями вперёд. Лимит `n ≤ 100` задан на уровне API.
